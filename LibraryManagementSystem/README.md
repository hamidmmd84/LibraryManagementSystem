# سیستم مدیریت کتابخانه (Java)

یک پروژه‌ی پایه برای درس برنامه‌سازی پیشرفته، پیاده‌سازی‌شده با Java Swing و ذخیره‌سازی دائمی روی دیتابیس SQLite.

## امکانات فعلی

- ثبت، ویرایش، جستجو و حذف کتاب
- ثبت، ویرایش، جستجو و حذف عضو
- جلوگیری از ثبت شابک تکراری و شماره دانشجویی تکراری
- ثبت امانت کتاب با مهلت ۱۴ روزه
- ثبت بازگشت کتاب و به‌روزرسانی تعداد نسخه‌های موجود
- نگهداری سابقه‌ی امانت‌ها و نمایش دیرکرد
- محاسبه‌ی جریمه‌ی دیرکرد با نرخ پایه‌ی ۱۰٬۰۰۰ تومان برای هر روز
- نمایش آمار خلاصه در بالای برنامه
- ذخیره‌ی دائمی اطلاعات در دیتابیس SQLite؛ داده‌ها پس از بستن و اجرای دوباره‌ی برنامه باقی می‌مانند
- رابط گرافیکی فارسی و راست‌چین

## پیش‌نیاز

- JDK 17 یا جدیدتر. برای بررسی نسخه‌ی جاوا می‌توان از این دستور استفاده کرد:

```bash
java -version
javac -version
```

- درایور JDBC اس‌کیو‌لایت: فایل `lib/sqlite-jdbc-3.53.4.0.jar` (وابستگی `org.xerial:sqlite-jdbc`). این فایل در پوشه‌ی `lib` همین پروژه قرار دارد؛ اگر نبود می‌توان آن را از Maven Central دانلود کرد:

```
https://repo1.maven.org/maven2/org/xerial/sqlite-jdbc/3.53.4.0/sqlite-jdbc-3.53.4.0.jar
```

## اجرا در ویندوز

فایل `run.bat` را اجرا کنید. این فایل ابتدا پروژه را کامپایل و سپس برنامه را اجرا می‌کند. در صورت اجرا از ترمینال نیز می‌توان در پوشه‌ی پروژه دستور زیر را زد:

```bat
run.bat
```

## اجرا در Linux یا macOS

```bash
./run.sh
```

## دیتابیس

- در اولین اجرا فایل `library.db` به‌صورت خودکار در پوشه‌ی پروژه ساخته و جدول‌های `books`، `members` و `loans` ایجاد می‌شوند؛ کاربر نباید چیزی را دستی اجرا کند.
- کتاب‌ها، اعضا و امانت‌ها پس از بستن و اجرای دوباره‌ی برنامه باقی می‌مانند. برای شروع از صفر کافی است فایل `library.db` را حذف کنید.
- اگر می‌خواهید دیتابیس در مسیر دیگری ساخته شود، مسیر آن را به‌عنوان آرگومان اول برنامه بدهید:

```bat
java -cp "out;lib\*" com.example.library.Main D:\my-library.db
```

(در Linux/macOS جداکننده‌ی classpath به‌جای `;` از `:` استفاده می‌کند.)

- تمام دستورهای SQL در لایه‌ی `repository` قرار دارند و از query پارامتری (`PreparedStatement`) استفاده می‌کنند؛ در رابط کاربری هیچ SQL وجود ندارد.
- عملیات امانت و بازگشت داخل یک transaction انجام می‌شوند تا موجودی کتاب و رکورد امانت هرگز ناسازگار نشوند؛ برای محکم‌کاری، کاهش موجودی با شرط `available_copies > 0` و ثبت بازگشت با شرط `return_date IS NULL` در خود دیتابیس گارد شده است.

## ساختار کد

```text
src/main/java/com/example/library/
├── Main.java                  ← نقطه‌ی شروع؛ راه‌اندازی دیتابیس و سرویس
├── db/
│   └── Database.java          ← اتصال SQLite، ساخت خودکار جدول‌ها، مدیریت transaction
├── model/
│   ├── Book.java
│   ├── Member.java
│   └── Loan.java
├── repository/
│   ├── BookRepository.java
│   ├── MemberRepository.java
│   ├── LoanRepository.java
│   ├── SqliteBookRepository.java
│   ├── SqliteMemberRepository.java
│   └── SqliteLoanRepository.java
├── service/
│   └── LibraryService.java    ← قوانین اصلی کتابخانه و اعتبارسنجی‌ها
└── ui/
    └── MainFrame.java         ← رابط گرافیکی Swing
```

- `model`: کلاس‌های داده و وضعیت موجودیت‌ها
- `db`: مدیریت اتصال، اسکیمای دیتابیس و transaction
- `repository`: لایه‌ی دسترسی به داده (DAO)؛ تمام SQL این‌جاست
- `service`: قوانین کسب‌وکار و اعتبارسنجی‌ها؛ از repositoryها استفاده می‌کند
- `ui`: رابط گرافیکی Swing
- `Main`: نقطه‌ی شروع برنامه

## قوانین ساده‌ی پروژه

- هر کتاب با شابک یکتا ثبت می‌شود.
- هر عضو با شماره‌ی دانشجویی یکتا ثبت می‌شود.
- تعداد نسخه‌ها نمی‌تواند کمتر از تعداد نسخه‌های امانت‌داده‌شده شود.
- حذف کتاب یا عضوی که سابقه‌ی امانت دارد برای حفظ سوابق مجاز نیست.
- نسخه‌ای که امانت داده شده باشد از فهرست نسخه‌های قابل امانت خارج می‌شود و هنگام بازگشت، دوباره موجود می‌شود.
